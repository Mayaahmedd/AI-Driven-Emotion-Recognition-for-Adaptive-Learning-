\chapter{Methodology}\label{chap:Methodology}

\section{Chapter Overview}\label{sec:method_overview}

This chapter explains how the proposed system is built. The system has two main parts. The first part is the emotion recognition module, which reads short webcam clips of the learner and predicts academic affective states. The second part is the adaptation module, which uses these predictions---together with simulated knowledge and engagement signals---to choose the next pedagogical action in a reinforcement-learning loop. The two parts are connected by a small interface that maps FER outputs to a discrete emotion label in the tutor's state vector.

The chapter is organised in two blocks. \textbf{Part~I} (Sections~\ref{sec:method_dataset}--\ref{sec:method_integration}) covers the Facial Expression Recognition (FER) module: data, preprocessing, architecture, training, metrics, and integration readiness. \textbf{Part~II} (Section~\ref{sec:method_rl_chapter} and its subsections) covers the adaptation module: MDP formulation, Gymnasium environment, synthetic student, reward design, PPO training, evaluation, ablation, and limitations. Quantitative results for both parts are reported in Chapter~\ref{chap:results}.

The proposed FER architecture is shown in Figure~\ref{fig:fer_pipeline}. A short video clip is first sampled and preprocessed. It is then passed through a deep visual feature extractor, a channel attention block, a temporal model, and a temporal attention layer. The output is one independent score per affective label. The reasoning behind this exact pipeline is explained step by step in the following sections.

\section{Dataset and Affect Labels}\label{sec:method_dataset}

The FER module is trained and evaluated on the DAiSEE dataset \cite{gupta_daisee_2016}. DAiSEE is a public dataset of about $9{,}068$ short webcam clips collected from $112$ students in study-like conditions, where each clip is annotated with four affective states: engagement, boredom, confusion, and frustration \cite{gupta_daisee_2016}. The original annotation scheme assigns each state an ordinal level from $0$ to $3$, but several recent FER works on DAiSEE simplify these levels into binary present/absent decisions because the most useful pedagogical information is whether a state is active during the clip rather than its exact intensity \cite{rao_recognition_2021,leong_deep_2020,abedi_improving_2021}.

Engagement, boredom, confusion, and frustration are kept as the target labels because they are the academic emotions that have repeatedly been shown to matter most during learning \cite{dmello_language_2012,pekrun_control-value_2006,tyng_influences_2017}. They are not the same as the basic emotions of happiness or fear that classical FER usually targets, and educational FER systematic reviews highlight that detecting them, rather than basic emotions, is what makes a model useful for tutoring and online classrooms \cite{lek_academic_2023,florestiyanto_emotion_2024,vistorte_integrating_2024}. DAiSEE was therefore selected as the main benchmark in this thesis because it is the standard public benchmark for these four states \cite{lek_academic_2023}.

A multilabel formulation is used, meaning that a single clip can be marked positive for several states at the same time, instead of being assigned to exactly one class. This matches what is observed in real DAiSEE annotations, where a learner can look both engaged and slightly confused, or both bored and slightly frustrated, in the same short clip \cite{gupta_daisee_2016}. Educational FER reviews also note that academic affect tends to overlap rather than appear in isolated single classes, which makes single-label classification a poor fit for this task \cite{lek_academic_2023,florestiyanto_emotion_2024}.

The dataset is split into the official DAiSEE training, validation, and test sets, exactly as released by Gupta et al.\ \cite{gupta_daisee_2016}. No clips are removed and no new split is created: the training set contains $5{,}358$ clips, the validation set contains $1{,}429$ clips, and the test set contains $1{,}784$ clips. The training set is used to fit the model parameters, the validation set is used to choose the best epoch and to tune per-label decision thresholds, and the test set is held out and only used at the end to report final metrics. This three-way split is the standard protocol used by recent DAiSEE studies \cite{abedi_improving_2021,mehta_three-dimensional_2022,su_leveraging_2024}.

\section{Data Preparation}\label{sec:method_preparation}

Each DAiSEE clip is first decoded into image frames in an offline preprocessing step. The decoder samples each ten-second clip at a low frame rate, producing a fixed sequence of $16$ frames per clip, which are stored as JPEG images on disk. The downstream FER model, however, expects a temporal axis of length $T = 24$, so a second per-batch sampling step is applied at training, validation, and test time. For each clip, $24$ indices are produced with \texttt{numpy.linspace} between $0$ and $15$, then cast to integers, which yields a deterministic sequence covering all $16$ source frames with a small number of repeated indices. Because the source clip already has fewer frames than the target length, the random starting-window logic for training-time temporal jitter is never actually triggered in the present setup; sampling is therefore the same at training and inference. The frames are loaded at a resolution of $224 \times 224$ pixels.

The choice of $T = 24$ was made for two reasons. First, academic affective states such as boredom or confusion build up over several seconds, so a single frame is not enough \cite{abedi_improving_2021,asaju_adaptive_2022}. Second, very long sequences make training slow and unstable on commodity GPUs, especially when a deep backbone is used per frame \cite{asaju_affects_2021}. A fixed length of $24$ time steps gives the BiLSTM a stable input shape across batches while keeping memory and time manageable.

Each frame is decoded with OpenCV, converted from BGR to RGB, resized to $224 \times 224$, normalised by dividing pixel values by $255$, and then standardised using the ImageNet mean $(0.485, 0.456, 0.406)$ and standard deviation $(0.229, 0.224, 0.225)$. ImageNet normalisation is used so that the inputs match the statistics of the data on which the ResNet50 backbone was originally pre-trained \cite{he_resnet_2016}. This is the standard preprocessing recipe followed by educational FER models that also start from ImageNet-pretrained backbones \cite{asaju_adaptive_2022,gupta_edfa_2023,aly_revolutionizing_2025}.

A small set of frame-level data augmentations is applied only at training time, never at validation or test time. Each frame can be horizontally flipped with probability $0.5$. Brightness and contrast can be jittered with probability $0.5$, by sampling a contrast factor uniformly between $0.85$ and $1.15$ and a brightness shift uniformly between $-15$ and $15$ pixel values. A small random rotation between $-7^{\circ}$ and $+7^{\circ}$ is applied with probability $0.25$, with reflective borders. Mild Gaussian blur with a $3 \times 3$ kernel is applied with probability $0.15$. Finally, a small random crop is applied with probability $0.25$, by sampling a crop ratio uniformly between $0.90$ and $1.0$ of the frame size and resizing back to $224 \times 224$. These augmentations are deliberately conservative. They simulate the kind of variation a webcam may introduce in a real classroom, such as small head rotations, lighting changes, slight motion blur, and partial face crops, which are exactly the situations that recent educational FER reviews report as the main practical sources of error \cite{lek_academic_2023,florestiyanto_emotion_2024,vistorte_integrating_2024}. Aggressive augmentations such as large rotations or strong colour distortions were avoided because they tend to destroy the very subtle facial cues that distinguish confusion and frustration.

A controlled oversampling step is also applied to the training set before training. The DAiSEE training labels are heavily imbalanced: most clips are labelled engaged, while clips marked confused or frustrated are far less common, a problem that almost every recent DAiSEE study has reported and tried to address \cite{gupta_daisee_2016,abedi_improving_2021,mehta_three-dimensional_2022,santoni_convolutional_2023,rianto_engagement_2025}. Oversampling means duplicating samples from minority groups so that the model sees them more often during training, while undersampling means dropping samples from majority groups; the literature on imbalanced learning has shown that oversampling tends to hurt minority recall less than undersampling in this kind of small-data setting \cite{santoni_convolutional_2023}.

The oversampling is applied on a dominant-group basis. Each training clip is assigned a single dominant group based on the priority order frustration, confusion, boredom, engagement; clips with no positive label fall into a separate group. Clips in the engagement group are kept once, clips in the boredom group are duplicated twice, clips in the confusion group three times, and clips in the frustration group four times. The duplication factors grow with how rare the group is, so that the rarest dominant states are seen most often during training. The full duplicated set is then shuffled with a fixed random seed for reproducibility. This is a controlled form of oversampling because the multipliers are fixed in advance and chosen from the original DAiSEE statistics, rather than letting an automatic resampler decide them. It is also less disruptive than synthetic methods like SMOTE that interpolate between samples in feature space \cite{santoni_convolutional_2023}, since here the original frames are reused without modification, and any acquisition variability is added back through the augmentation pipeline above. Figure~\ref{fig:fer_oversampled_dist} shows the resulting positive-clip count for each label after this controlled oversampling has been applied to the DAiSEE training set.

\section{Proposed FER Architecture}\label{sec:method_architecture}

The proposed architecture, summarised in Figure~\ref{fig:fer_pipeline}, takes a tensor of shape $[B, T, C, H, W]$ as input, where $B$ is the batch size, $T = 24$ is the length of the temporal axis fed to the model (built from the $16$ decoded frames per clip with the linear-interpolation sampling described in Section~\ref{sec:method_preparation}), $C = 3$ is the number of colour channels, and $H = W = 224$ is the spatial resolution. The output is a vector of four sigmoid scores per clip, one for each of boredom, engagement, confusion, and frustration. The pipeline contains five blocks: a spatial backbone, a channel attention block, a temporal recurrent encoder, a temporal attention pooler, and a multilabel classification head. Each block is described below, in the same order as in Figure~\ref{fig:fer_pipeline}.

\subsection{Spatial Backbone: ResNet50}\label{sec:method_resnet}

The spatial backbone is ResNet50 \cite{he_resnet_2016}. ResNet50 is a Convolutional Neural Network with $50$ layers that uses residual connections, which are shortcut paths that skip over groups of layers and add the input of a block back to its output \cite{he_resnet_2016}. Without these connections, very deep networks become hard to train, because the gradients used to update the early layers shrink as they pass through many layers \cite{he_resnet_2016}. The residual design fixes this and allows much deeper networks to be trained reliably, which is why ResNet50 has become a standard image feature extractor for many vision tasks, including educational FER \cite{asaju_adaptive_2022,asaju_affects_2021,gupta_edfa_2023,aly_revolutionizing_2025}.

ResNet50 is loaded with weights that were pre-trained on ImageNet and is fine-tuned end-to-end during training, rather than frozen. Pre-training means that the network has already learned generic visual filters, such as edges, textures, parts of faces, and lighting patterns, before this project starts \cite{he_resnet_2016}. Fine-tuning means that these filters are then adjusted on DAiSEE so that they capture cues that matter for academic affect, such as eyebrow shape, eye opening, mouth tension, or head orientation. This transfer-learning strategy is standard in educational FER, where datasets are too small to train such a deep network from random initialisation \cite{komaravalli_detecting_2023,gupta_edfa_2023,aly_revolutionizing_2025}.

To use ResNet50 as a pure feature extractor, its original $1000$-class ImageNet head is removed, leaving the convolutional body and the global pooling layer. For each input frame, the body produces a $2048$-dimensional feature vector that summarises the appearance of that frame. The $T = 24$ frames of a clip are passed through the backbone in a single batched call by reshaping the input to $[B \cdot T, C, H, W]$, and the resulting features are reshaped back to $[B, T, 2048]$ before the next block. This design keeps GPU usage efficient and matches how previous CNN-plus-temporal models on DAiSEE process clips frame by frame \cite{abedi_improving_2021,asaju_adaptive_2022,shiri_detection_2024}.

\subsection{Squeeze-and-Excitation Channel Attention}\label{sec:method_se}

After ResNet50, the per-frame feature vectors pass through a Squeeze-and-Excitation (SE) block, adapted from the original Squeeze-and-Excitation Networks design \cite{hu_squeeze_2018}. An SE block is a small attention module that learns, for each frame, which of the $2048$ feature channels are more useful and which can be down-weighted \cite{hu_squeeze_2018}. It does this with two small fully connected layers: the first reduces the $2048$-dimensional vector to a hidden size of $\max(2048 / 16, 64) = 128$ with a ReLU activation, and the second projects it back to $2048$ with a sigmoid activation, producing one importance weight per channel. These weights are then multiplied element-wise back onto the original features, so each channel is rescaled by its learned importance.

The reason for using SE attention here is that ResNet50 was trained on ImageNet, where the most informative channels are not necessarily those that matter for facial affect in a learning context \cite{he_resnet_2016}. The SE block lets the network re-weight ResNet50 features so that channels that respond to confusion-, boredom- or frustration-relevant cues are emphasised, and noisy ones are suppressed. Recent educational FER systems have used closely related channel-and-spatial attention modules, such as CBAM, on top of similar backbones for the same reason \cite{aly_revolutionizing_2025,liu_dynamic_nodate}. Compared with full CBAM, the SE variant used here is lighter, since it acts only on channels and does not add a spatial attention sub-module, which keeps the model small enough to be trained on a single GPU.

\subsection{Temporal Encoder: Two-Layer BiLSTM}\label{sec:method_bilstm}

The frame-level features are then passed to a two-layer Bidirectional Long Short-Term Memory network, or BiLSTM. A Long Short-Term Memory network is a type of Recurrent Neural Network designed to keep useful information from earlier time steps and forget less useful information through learned gates \cite{hochreiter_lstm_1997}. A bidirectional version reads the same sequence both forward and backward and concatenates the two hidden states at each time step, so each frame is encoded with knowledge of both the past and the future of the clip \cite{hochreiter_lstm_1997,asaju_adaptive_2022,tulsani_realtime_2025}. This is useful for academic affect, because cues like a delayed nod after a confusing question, or a short smile after a difficult problem, only become meaningful when the frames before and after are also taken into account.

The BiLSTM in this thesis has two stacked layers with hidden size $256$ in each direction, dropout $0.5$ between stacked layers, and reads the $[B, T, 2048]$ sequence produced by the SE block. Its output has shape $[B, T, 512]$, where $512 = 2 \cdot 256$ comes from concatenating the forward and backward hidden states. Stacking two layers, instead of one, lets the network represent affective patterns at different time scales: the lower layer can capture short, frame-to-frame transitions, while the upper layer can capture slower trends across the whole clip. Recent DAiSEE pipelines that combine a CNN backbone with a BiLSTM have shown that this kind of temporal recurrence is one of the strongest single design choices for engagement and affect recognition \cite{asaju_adaptive_2022,asaju_affects_2021,shiri_detection_2024,tulsani_realtime_2025}.

\subsection{Temporal Attention Pooling}\label{sec:method_temporal_attention}

A clip-level prediction must be made from $T = 24$ time-step vectors. A simple way would be to take the last hidden state of the BiLSTM, but this gives all the influence to the last frames of the clip and ignores the rest. Another simple option would be to average all $T$ vectors, but this gives equal weight to every frame, including ones where the face is occluded, the learner blinks, or the head turns away from the screen. A temporal attention layer is used instead.

The temporal attention layer is a small two-step network adapted from the general attention mechanism used in modern sequence models \cite{vaswani_attention_2017,mehta_three-dimensional_2022,su_leveraging_2024}. For each of the $T$ time-step vectors, it computes an unnormalised score with a fully connected layer of hidden size $128$ and a $\tanh$ activation, followed by another fully connected layer that produces a single scalar. The $T$ scalars are then turned into non-negative weights that sum to one with a softmax across time, and the final clip representation is the weighted sum of the time-step vectors with these weights. The output therefore has shape $[B, 512]$ and represents a weighted summary of the whole clip, where each frame contributes according to how relevant it is for the affective decision. The same idea, often called attention pooling, has been used in other DAiSEE-based engagement detectors and tends to focus on the most expressive frames in the clip \cite{mehta_three-dimensional_2022,su_leveraging_2024,liu_dynamic_nodate}.

\subsection{Multilabel Classification Head}\label{sec:method_head}

The clip representation is passed through a small classification head that outputs one logit per affective label. The head is a sequence of dropout, a linear projection to $256$ units, a ReLU activation, another dropout, and a final linear projection to $4$ logits. Both dropout layers use a dropout rate of $0.5$, which randomly zeroes half of the units during training and is a standard regulariser used in many recent DAiSEE pipelines \cite{asaju_adaptive_2022,shiri_detection_2024}.

A sigmoid activation is then applied to each of the four logits independently, producing a value between $0$ and $1$ for each label. These values are interpreted as the probability that the corresponding affective state is active in the clip. Because the sigmoid is applied to each label separately, the four predictions do not need to sum to one, which is exactly what multilabel classification requires \cite{rianto_engagement_2025}. This is different from a softmax head, which would force the four labels to compete with each other for the same probability mass and would make it impossible to predict, for example, that a learner is both engaged and slightly confused at the same time. The four sigmoid scores correspond, in order, to boredom, engagement, confusion and frustration, matching the DAiSEE label set \cite{gupta_daisee_2016}. They are turned into final binary predictions in the threshold-tuning step described in Section~\ref{sec:method_training}.

\section{Training Strategy}\label{sec:method_training}

The model is trained end-to-end. Both the ResNet50 backbone and the upper temporal blocks are updated by gradient descent. End-to-end training means that the visual feature extractor is allowed to specialise on educational facial cues during training, rather than staying fixed on generic ImageNet features. Recent educational FER work that fine-tunes the backbone, instead of freezing it, has reported clear gains compared with frozen-backbone variants on DAiSEE-style data \cite{abedi_improving_2021,gupta_edfa_2023,aly_revolutionizing_2025}.

\subsection{Loss Function and Class Imbalance}\label{sec:method_loss}

The loss function is the per-label binary cross-entropy with logits, with a positive-class weight per label. Binary cross-entropy is the standard loss for binary decisions, and applying it independently to each of the four labels turns it into a natural multilabel loss \cite{rianto_engagement_2025}. The per-label positive-class weight is computed from the training set as the ratio of negatives to positives for that label, then clipped to the interval $[0.5, 6.0]$ so that a single very rare class cannot dominate the gradient. This mirrors the weighted cross-entropy strategies used by other DAiSEE works that explicitly target class imbalance \cite{abedi_improving_2021,mehta_three-dimensional_2022,rianto_engagement_2025}.

This weighted loss complements the controlled oversampling described in Section~\ref{sec:method_preparation}: oversampling makes the model see minority groups more often, while the per-label weight makes a missed positive on a minority label more costly than a missed negative. The two together follow the imbalance-aware design pattern recommended by recent DAiSEE studies and by educational FER reviews more broadly \cite{abedi_improving_2021,mehta_three-dimensional_2022,santoni_convolutional_2023,rianto_engagement_2025,lek_academic_2023}.

\subsection{Optimisation}\label{sec:method_optim}

The model is optimised with AdamW. AdamW is a popular adaptive optimiser that keeps a running estimate of the gradient and its variance for each parameter and applies a separate weight-decay term. It is also the optimiser used by many recent DAiSEE pipelines \cite{shiri_detection_2024,tulsani_realtime_2025}. The learning rate is set to $5 \times 10^{-5}$, which is a small value chosen so that the pre-trained backbone is updated gently and does not lose its ImageNet knowledge. The weight-decay coefficient is $10^{-5}$. The batch size is $4$, which is a small value imposed by the high memory cost of running a $50$-layer backbone on $24$ frames per clip. Gradients are clipped at a maximum global norm of $5.0$ to avoid occasional large updates that could destabilise training, a common safeguard in recurrent architectures.

A learning-rate scheduler of type \texttt{ReduceLROnPlateau} watches the validation Macro F1 score. If the Macro F1 does not improve for two consecutive validation rounds, the learning rate is multiplied by $0.5$. The model is trained for up to $12$ epochs, with an early-stopping rule that interrupts training if the validation Macro F1 does not improve for four epochs in a row. The best checkpoint is the one with the highest validation Macro F1, not the one from the last epoch. This validation-driven model selection is the same protocol followed by recent DAiSEE engagement detectors that report careful imbalance-aware evaluation \cite{abedi_improving_2021,shiri_detection_2024,su_leveraging_2024}.

\subsection{Per-Label Threshold Tuning}\label{sec:method_thresholds}

Once the sigmoid scores have been computed, a threshold must be chosen for each label to produce a binary decision. A common default is to use $0.5$ for every label, but this default is rarely optimal in imbalanced multilabel settings, because it does not account for the different prior probabilities of different labels \cite{rianto_engagement_2025}. A per-label threshold tuning step is therefore included in the training pipeline.

After every epoch, the validation set is scored once with the current model, producing a probability matrix of size $N_{\mathrm{val}} \times 4$. For each of the four labels, a grid of candidate thresholds is searched over the values $0.10, 0.15, 0.20, \dots, 0.70$, in steps of $0.05$. For each candidate, the corresponding binary predictions are formed and the per-label F1 score is computed against the ground truth. The threshold that maximises the per-label F1 is kept for that label. The four chosen thresholds are then reused on the validation set to compute the global metrics that are reported each epoch. The thresholds saved with the best checkpoint are the ones used at test time. This procedure is consistent with how prior DAiSEE works adapt their decision thresholds when class imbalance is present, rather than fixing them at $0.5$ \cite{rianto_engagement_2025,mehta_three-dimensional_2022}.

\section{Evaluation Metrics}\label{sec:method_metrics}

Reporting only one global accuracy is not enough on this task, because accuracy can be misleading on imbalanced multilabel data, where a model that always predicts the majority labels can already look competitive \cite{lek_academic_2023,rianto_engagement_2025}. The evaluation in this thesis therefore uses several complementary metrics, all of them computed with the per-label thresholds described in Section~\ref{sec:method_thresholds}.

The first set is the F1 family. The F1 score is the harmonic mean of precision and recall: precision is the fraction of predicted positives that are actually positive, and recall is the fraction of real positives that are correctly retrieved \cite{rianto_engagement_2025}. Macro F1 is the average of the per-label F1 scores, where each label contributes equally regardless of its frequency. Weighted F1 is the same average but each per-label F1 is weighted by the number of real positives for that label, so frequent labels count more. Micro F1 is computed by pooling all the predictions across labels and computing one global F1 from those pooled counts. Samples F1 is computed per clip, by treating each clip as its own multilabel example and averaging the resulting F1 over clips. These four variants are the same family of multilabel F1 metrics used by recent DAiSEE-style and multilabel FER works \cite{rianto_engagement_2025,fu_integrating_2025,mehta_three-dimensional_2022}.

A complementary metric is exact-match accuracy, which counts a prediction as correct only when all four labels are correctly predicted for the clip. This is a strict criterion: a clip with three labels right and one label wrong is counted as a full miss. It is reported because it shows how often the system is fully aligned with the ground truth, which is a relevant quality for downstream adaptation that consumes the full label vector. Per-label accuracy is also reported for each of the four labels, since it gives a class-by-class view of how the model behaves and helps diagnose which labels are still hard.

\section{Design Rationale and Justification}\label{sec:method_design_rationale}

This section explains the reasoning behind the main design choices in the proposed FER pipeline. The justifications presented here are conceptual rather than experimental: they are grounded in what the educational FER literature reports as effective designs, in the structural properties of the DAiSEE dataset, and in the practical engineering constraints of training on a single consumer-grade GPU. The empirical evidence supporting these choices, including a side-by-side comparison of the selected configuration against alternative backbones, alternative temporal modules, and ablations of the imbalance-handling components, is reported separately as part of the architecture-selection experiments in Section~\ref{sec:results_fer_arch_selection}.

\textbf{Why ResNet50 rather than a deeper or transformer-based backbone.} ResNet50 is used because it provides a strong visual feature extractor at a controlled compute and memory cost \cite{he_resnet_2016}. Larger CNN backbones such as ResNet-152 or EfficientNetV2-L have been used on DAiSEE \cite{asaju_adaptive_2022,shiri_detection_2024}, and Vision Transformer or 3D-attention models have also been reported to improve four-class engagement detection \cite{mehta_three-dimensional_2022,su_leveraging_2024,liu_dynamic_nodate}. These models typically require more memory, more careful training schedules, or more training data than DAiSEE provides, and recent reviews observe that their gain on DAiSEE is small relative to the additional deployment cost \cite{lek_academic_2023,vistorte_integrating_2024}. ResNet50 with channel attention therefore sits in the middle of this accuracy--cost trade-off and is a conceptually sound default for an educational FER pipeline that should also run on standard hardware.

\textbf{Why a BiLSTM rather than a 3D CNN or temporal transformer.} A BiLSTM is used because it is an explicit sequence model that can be combined with a strong 2D backbone without doubling the parameter count, and because BiLSTM-based DAiSEE pipelines remain among the most reliable temporal designs in the literature \cite{asaju_adaptive_2022,asaju_affects_2021,tulsani_realtime_2025,shiri_detection_2024}. 3D CNNs such as C3D or 3D DenseNet, and temporal transformers, have been proposed for DAiSEE \cite{gupta_daisee_2016,mehta_three-dimensional_2022,su_leveraging_2024,liu_dynamic_nodate}, but they require more memory per clip and are harder to train stably at the small batch sizes that fit on a single consumer-grade GPU.

\textbf{Why multilabel rather than single-label classification.} A single-label formulation would force the model to choose only one of the four affective states per clip, which contradicts both the DAiSEE annotations and the way academic affect tends to co-occur in real clips \cite{gupta_daisee_2016,dmello_language_2012}. Recent reviews of educational FER also recommend treating affect as several co-occurring states rather than as a single mutually exclusive class \cite{lek_academic_2023,florestiyanto_emotion_2024}. The multilabel design adopted here is therefore the formulation that matches both the underlying labels and the pedagogical reality.

\textbf{Why imbalance-aware training with both oversampling and weighted loss.} Imbalance is not a side issue in DAiSEE; it is a defining property of the dataset \cite{gupta_daisee_2016,abedi_improving_2021}. Several DAiSEE-focused studies have shown that, without explicit imbalance handling, models collapse onto the majority class and produce nearly unusable minority-class metrics \cite{santoni_convolutional_2023,rianto_engagement_2025}. The combined design used here---controlled oversampling at the data level, weighted binary cross-entropy at the optimisation level, and per-label threshold tuning at the decision level---addresses imbalance at three different stages, which is more robust than relying on any single mechanism.

\textbf{Why per-label thresholds rather than the default $0.5$.} The four labels have very different prior probabilities in DAiSEE. A fixed threshold of $0.5$ for all labels would suppress too many positives on rare labels and would collapse minority recall. Per-label thresholds, tuned on the validation set, are a simple and inexpensive way to keep the model usable on rare labels without retraining, in line with the imbalance-aware decision strategies used by recent DAiSEE pipelines \cite{rianto_engagement_2025,mehta_three-dimensional_2022}.

\textbf{Webcam-only design.} The whole pipeline takes only a video clip as input. There are no physiological sensors, no microphone, and no extra wearable. This is a deliberate constraint. Recent reviews of educational FER and emotion-aware tutoring have repeatedly noted that multimodal sensor stacks are expensive, fragile, and hard to deploy at scale in real classrooms or online courses \cite{vistorte_integrating_2024,fernandez-herrero_evaluating_2024,florestiyanto_emotion_2024}. A webcam-only system runs on the hardware that online learners already have, which is the main reason for keeping the FER module unimodal in this thesis.

These design choices were also validated empirically through a series of architecture-selection experiments in which alternative backbones, alternative temporal modules, and ablations of the imbalance-handling components were trained under matched protocols and compared against the configuration described above; the corresponding measurements are reported in Section~\ref{sec:results_fer_arch_selection}.

\section{Implementation and Reproducibility Details}\label{sec:method_reproducibility}

All experiments are implemented in Python with PyTorch and torchvision. Frame I/O uses OpenCV, and metrics are computed with scikit-learn. The dataset class, model class, training script, and evaluation script are organised in separate files inside the experiment folder and are kept self-contained, so that the same training run can be reproduced from a single command. \section{Integration Readiness for Adaptive Learning}\label{sec:method_integration}

The FER module is designed to be a clean input source for the adaptation module, not an end product on its own. At inference time, the module takes a $24$-frame webcam clip and returns a four-dimensional emotion vector, where each component is the per-label sigmoid score for boredom, engagement, confusion, and frustration. These scores are continuous values between $0$ and $1$, computed with the same per-label thresholds as during evaluation, which makes the output stable across clips. The adaptation module described in the next section consumes this vector together with simple performance signals, such as whether the previous answer was correct, to choose the next teaching action and the next question.

This separation between perception and decision has practical advantages. It allows the FER module to be retrained or replaced without changing the adaptation logic, as long as the output interface remains a four-dimensional emotion vector. It also allows the adaptation module to be evaluated under different emotional input conditions, including the case where the FER module is replaced by a no-emotion baseline, which is the comparison setup used later in this thesis. Finally, because the FER module only requires a webcam, the integrated system inherits the same lightweight deployment profile, which is in line with the FER-only adaptive design promoted by recent educational FER reviews \cite{lek_academic_2023,florestiyanto_emotion_2024,vistorte_integrating_2024}. The exact way this emotion vector is fed into the adaptation policy, and how the policy is trained and evaluated, is described in Section~\ref{sec:method_rl_chapter} and its subsections below.

\section{Adaptive Tutoring via Reinforcement Learning}\label{sec:method_rl_chapter}

\subsection{Introduction to Methodology}\label{sec:method_rl_intro}

This section describes the \emph{adaptation module}: how a reinforcement-learning (RL) agent selects pedagogical actions for a synthetic student in a Gymnasium-compatible environment. The module is separate from the facial expression recognition (FER) pipeline in Section~\ref{sec:method_integration}, but it is designed so that FER outputs can replace the default emotion signal when live deployment is enabled.

The research question addressed here is operational: given a compact student state (knowledge, engagement, affect-related scalars, and a discrete emotion label), which teaching action should the tutor take next to improve learning outcomes while limiting harmful affect? Training on real students during policy search is avoided for ethical, practical, and reproducibility reasons \cite{azoulay_adaptive_2021,perez_emotions_2024,fernandez-herrero_evaluating_2024}. Instead, a population of synthetic students approximates diverse learning and emotional dynamics offline. The learned policy is then evaluated in the same simulator under fixed protocols and compared to rule-based and random baselines.

What follows is organised around the mandatory components of an RL systems paper: architecture, MDP formulation, environment API, student model, reward design, PPO training, evaluation, and limitations. Items marked as \emph{future work} are interfaces present in code but not used in the main experiments reported in this thesis (for example, \texttt{USE\_REAL\_FER = False} by default).

\subsection{System Architecture}\label{sec:method_rl_architecture}

Figure~\ref{fig:rl_architecture} illustrates the interaction between the RL tutor and the synthetic student. The loop is standard for Gymnasium: the environment exposes an observation; the agent selects an action; the environment advances the student state and returns reward and termination flags.

\paragraph{Components.}
\begin{itemize}
    \item \textbf{Environment} (\texttt{StudentEnv}): implements reset, step, action masking, episode limits, and reward computation.
    \item \textbf{Synthetic student} (\texttt{SyntheticStudent}): updates knowledge and affect scalars after each action.
    \item \textbf{FER interface} (\texttt{FERAdapter}): maps state or live FER labels to a discrete \texttt{emotion\_id} in $\{0,\ldots,3\}$.
    \item \textbf{Agent}: primary method is Proximal Policy Optimization (PPO) with invalid-action masking (\texttt{MaskablePPO}); DQN, LinUCB+DQN hybrid, rule-based, and random agents serve as baselines.
    \item \textbf{Reward engine} (\texttt{compute\_reward}): multi-term scalar reward, clipped to $[-1,1]$.
    \item \textbf{Evaluation}: fixed episode counts, seed aggregation, ablation, and sensitivity scripts.
\end{itemize}

\paragraph{Interaction pipeline.}
At each decision step $t$:
\begin{enumerate}
    \item The agent receives observation $\mathbf{o}_t \in \mathbb{R}^6$ and an action mask $\mathbf{m}_t \in \{0,1\}^{10}$.
    \item It selects action $a_t \in \{0,\ldots,9\}$ with $m_{t,a_t}=1$.
    \item The student model transitions from $\mathbf{s}_t$ to $\mathbf{s}_{t+1}$.
    \item The environment updates \texttt{emotion\_id} (synthetic thresholds or live FER).
    \item Reward $r_t$ is computed from $(\mathbf{s}_t, a_t, \mathbf{s}_{t+1})$ and auxiliary flags.
    \item Termination or truncation is evaluated; cooldown counters and persistent-frustration logic are updated.
\end{enumerate}

\paragraph{Training vs.\ inference.}
\emph{Training} rolls out many episodes over $50{,}000$ environment steps per algorithm and random seed, updating PPO weights with on-policy batches. \emph{Inference} (evaluation) loads a saved checkpoint and acts deterministically with masking, without gradient updates. Both phases use the same \texttt{StudentEnv} dynamics; only exploration noise (PPO entropy bonus) differs during training.

\subsection{Reinforcement Learning Formulation}\label{sec:method_rl_formulation}

Reinforcement learning models sequential decision making: an agent interacts with an environment, receives rewards, and learns a policy that maximises long-term return \cite{sutton_rl_book_2018}. In educational tutoring, the agent is the automated tutor; the environment is the student plus task context; actions are pedagogical interventions; rewards encode learning and well-being objectives.

The implementation treats each tutoring session as an \emph{episode} of up to $T_{\max}=50$ steps. Episodes end when the student reaches high mastery, drops out due to sustained frustration, or hits the step horizon. The discount factor $\gamma=0.99$ weights future rewards, which matches the config default and reflects that later knowledge gains still matter within a session.

\subsection{Markov Decision Process Definition}\label{sec:method_mdp}

The adaptive tutor is formalised as a Markov Decision Process (MDP) $\mathcal{M} = (\mathcal{S}, \mathcal{A}, P, R, \gamma)$ \cite{sutton_rl_book_2018}.

\paragraph{State space $\mathcal{S}$.}
The latent student state is a vector
\begin{equation}
    \mathbf{s}_t = \bigl(k_t,\; e^{\mathrm{eng}}_t,\; f_t,\; c_t,\; b_t,\; \iota_t\bigr),
    \label{eq:student_state}
\end{equation}
where $k_t \in [0,1]$ is knowledge level, $e^{\mathrm{eng}}_t$ is engagement, $f_t$ frustration, $c_t$ confusion, $b_t$ boredom, and $\iota_t \in \{0,1,2,3\}$ is \texttt{emotion\_id} (confused, bored, frustrated, engaged). All continuous components are clipped to $[0,1]$ after each transition. Confidence from the FER module is \emph{not} part of $\mathbf{s}_t$; it is stored in the step \texttt{info} dictionary for explainability only.

\paragraph{Action space $\mathcal{A}$.}
There are $|\mathcal{A}| = 10$ discrete actions (Table~\ref{tab:actions}). They cover difficulty adjustment, support, motivation, metacognition, and explanation---not a single ``next item'' decision alone.

\paragraph{Transition dynamics $P$.}
Transitions are implemented by \texttt{SyntheticStudent.apply\_action}: deterministic action-specific deltas plus Gaussian noise $\mathcal{N}(0, 0.02)$ on each affected dimension (\texttt{TRANSITION\_NOISE\_STD}). Personality parameters $(\gamma_s, \beta_s, \lambda_s, \rho_s)$ scale learning rate, sensitivity to difficulty, forgetting, and patience. This is a \emph{simulated} transition model, not an empirically fitted cognitive model.

\paragraph{Reward function $R$.}
The scalar reward $r_t = R(\mathbf{s}_t, a_t, \mathbf{s}_{t+1}, \text{flags})$ is described in Section~\ref{sec:method_reward}. Importantly, action IDs do not enter the reward formula directly; pedagogical preferences are encoded via state transitions, masking, and the optional ``optimal zone'' bonus.

\paragraph{Discount and return.}
The objective is to maximise expected discounted return
\begin{equation}
    G_t = \sum_{k=0}^{\infty} \gamma^k r_{t+k}, \qquad \gamma = 0.99.
    \label{eq:return}
\end{equation}
Equation~\eqref{eq:return} means that immediate and future rewards both contribute, but rewards farther in the future are weighted less. This is appropriate for tutoring sessions where early frustration can prevent later learning.

\paragraph{Partial observability.}
The agent observes $\mathbf{o}_t = \mathbf{s}_t$ (same six dimensions). There is no hidden state in the implementation: the MDP is fully observed from the agent's perspective. Real deployments would introduce partial observability (noisy FER, latent motivation); that is discussed under limitations.

\subsection{Gymnasium Environment Design}\label{sec:method_gymnasium}

The environment follows the Gymnasium API (successor to OpenAI Gym) \cite{towers_gymnasium_2023,axak_adaptive_nodate}. This choice is deliberate:
\begin{itemize}
    \item \textbf{Stable-Baselines3 compatibility}: standard \texttt{reset}/\texttt{step} contract for PPO and DQN.
    \item \textbf{Modularity}: student model, reward, and FER adapter are separate modules; the env orchestrates them.
    \item \textbf{Reproducibility}: seeds control population sampling and transitions.
    \item \textbf{Benchmarking}: same interface as other RL education simulators (e.g.\ comparative studies in simulation \cite{azoulay_adaptive_2021,weitekamp_tutorgym_2025}).
\end{itemize}

\paragraph{Environment loop (pseudo-code).}
\begin{verbatim}
env = StudentEnv(population_seed=seed)
obs, info = env.reset(seed=seed)
done = False
while not done:
    mask = info["action_masks"]          # shape (10,), 1 = allowed
    action = agent.predict(obs, mask)    # MaskablePPO respects mask
    obs, reward, terminated, truncated, info = env.step(action)
    done = terminated or truncated
\end{verbatim}

\paragraph{\texttt{reset()}.}
A student is sampled uniformly from a fixed population of $N=10{,}000$ synthetic profiles. Initial knowledge is drawn from $\mathcal{U}(0.1, 0.5)$; engagement from $\mathcal{U}(0.4, 0.8)$; frustration, confusion, and boredom from low ranges. Cooldown timers and persistent-frustration flags are cleared. The return value is $(\mathbf{o}_0, \texttt{info})$ with an initial action mask.

\paragraph{\texttt{step(action)}.}
If the action is masked, the environment raises an error (hard constraint). Otherwise the student transitions, emotion is updated, reward is computed, cooldowns decrement, and termination rules apply. The five-tuple follows Gymnasium v0.29+: \texttt{terminated} (natural end), \texttt{truncated} (time limit), and \texttt{info} (diagnostics).

\paragraph{Termination and truncation.}
\begin{itemize}
    \item \textbf{Terminated (success)}: $k_{t+1} \geq 0.95$ (mastery).
    \item \textbf{Terminated (dropout)}: persistent frustration flag active for $\geq 5$ consecutive steps (\texttt{PERSISTENT\_FLAG\_DROPOUT\_STEPS}).
    \item \textbf{Truncated}: step count $\geq 50$ (\texttt{MAX\_EPISODE\_STEPS}).
\end{itemize}
Dropout is treated as a failure mode analogous to a student leaving a session due to sustained negative affect \cite{dmello_language_2012,govea_implementation_2024}.

\subsection{Observation Space}\label{sec:method_observation}

The observation space is \texttt{Box(6,)} with bounds $[0,1]$ for dimensions $0$--$4$ and $[0,3]$ for \texttt{emotion\_id}:
\begin{equation}
    \mathbf{o}_t = \bigl(k_t,\; e^{\mathrm{eng}}_t,\; f_t,\; c_t,\; b_t,\; \iota_t\bigr)^\top \in \mathbb{R}^6.
    \label{eq:observation}
\end{equation}
Equation~\eqref{eq:observation} is exactly the implementation vector returned by \texttt{StudentState.as\_vec()}. In ablation mode (\texttt{ablation\_no\_emotion=True}), dimension $5$ is forced to $0$ so the policy cannot use emotion identity, while affect scalars remain visible.

\paragraph{Why these variables?}
Knowledge and engagement link directly to learning constructs used in ITS research \cite{zerkouk_comprehensive_2025,guzman_developing_2025,dmello_language_2012}. Frustration, confusion, and boredom align with academic emotions targeted by the FER module (DAiSEE labels map to discrete \texttt{emotion\_id} at the interface). Using both continuous affect and a discrete emotion supports policies that threshold emotions for masking and rules while still reading graded signals.

\subsection{Action Space}\label{sec:method_action_space}

The action space is \texttt{Discrete(10)}. Actions not only change content difficulty but also metacognitive and motivational interventions, which matches the multi-dimensional adaptation gap identified in the literature review.

\paragraph{Action masking.}
Invalid actions are removed before the policy samples. Masking rules (implemented in \texttt{get\_action\_mask}) include:
\begin{itemize}
    \item If \textbf{persistent frustration} is active: only emergency actions $\{$\texttt{change\_pacing}, \texttt{autonomy\_support}, \texttt{explanation}$\}$ are allowed.
    \item Block \texttt{harder\_question} when $f > 0.6$ or $\iota =$ frustrated.
    \item Block \texttt{reflection\_prompt} when engagement $< 0.5$.
    \item Block \texttt{strategy\_guidance} when $f > 0.8$.
    \item Block \texttt{autonomy\_support} when $k < 0.4$.
    \item Block \texttt{scaffold} when $k \geq 0.5$.
    \item Per-action \textbf{cooldowns} after use (e.g.\ hint cooldown $3$ steps).
\end{itemize}
Masking encodes domain constraints so the learner cannot repeatedly apply harmful actions; PPO uses \texttt{sb3\_contrib.MaskablePPO} so invalid logits are excluded \cite{schulman_ppo_2017,guzman_developing_2025}.

\subsection{Reward Function Design}\label{sec:method_reward}

The reward is \emph{shaped}: dense feedback every step rather than a single sparse terminal score. This speeds credit assignment in a short horizon (50 steps) but risks reward hacking if terms conflict; masking and clipping mitigate extremes.

\paragraph{Components.}
Let $\mathbf{s}_t$ and $\mathbf{s}_{t+1}$ be successive states. Define normalized knowledge gain (Hake-style gain on remaining headroom) \cite{hake_normalized_gain_1998}:
\begin{equation}
    \Delta k_{\mathrm{norm}} = \mathrm{clip}\!\left(
        \frac{k_{t+1} - k_t}{1 - k_t + \varepsilon},\; -1,\; 1
    \right), \qquad \varepsilon = 10^{-8}.
    \label{eq:delta_k_norm}
\end{equation}
Equation~\eqref{eq:delta_k_norm} divides raw gain by remaining room to mastery. When $k_t$ is already high, the same absolute increment yields a smaller normalized value, which prevents the agent from receiving oversized rewards for tiny improvements near ceiling. The clip keeps gradients stable \cite{mnih_dqn_2015}.

Engagement change is $\Delta e = e^{\mathrm{eng}}_{t+1} - e^{\mathrm{eng}}_t$. Confusion and boredom enter as penalties $-c_{t+1}$ and $-b_{t+1}$ (level-based, not delta). Frustration uses a tiered term: no extra penalty in mid-range ``productive'' frustration; penalty $-0.5$ if $f_{t+1} > 0.6$; penalty $-1.0$ if persistent frustration flag is on. A \textbf{flow-zone bonus} $+1.0$ applies when all of the following hold: $k>0.5$, $e^{\mathrm{eng}}>0.6$, $f<0.3$, $c<0.4$, $b<0.3$ (Csikszentmihalyi-style optimal zone \cite{perez_emotions_2024,csikszentmihalyi_flow_1990}). Finally, a wrong-answer penalty $-0.5$ applies when the simulated last answer was incorrect.

\paragraph{Combined reward.}
Default weights use equal contribution $W = 1/7$ per term (Dawes-style equal weighting when relative importance is not empirically fixed \cite{dawes_improper_linear_1979}):
\begin{align}
    r_t &= \mathrm{clip}\Bigl(
        W_k \Delta k_{\mathrm{norm}}
        + W_e \Delta e
        - W_c c_{t+1}
        - W_b b_{t+1}
        + W_f \phi(f_{t+1})
        + W_z \mathbb{1}_{\mathrm{zone}}
        - W_w \mathbb{1}_{\mathrm{wrong}}
    ,\; -1,\; 1\Bigr).
    \label{eq:reward_total}
\end{align}
In Equation~\eqref{eq:reward_total}, $\phi$ is the frustration term described above, $\mathbb{1}_{\mathrm{zone}}$ is $1$ in the optimal zone and $0$ otherwise, and $\mathbb{1}_{\mathrm{wrong}}$ indicates a simulated incorrect response. Sensitivity analysis overrides $W_k$, $W_e$, etc., via \texttt{USE\_SENSITIVITY\_WEIGHTS}.

\paragraph{Design choices.}
\begin{itemize}
    \item \textbf{Dense vs.\ sparse}: dense rewards guide PPO within 50 steps; terminal mastery alone would be too sparse.
    \item \textbf{No action ID in $R$}: avoids trivial policies that chase action-specific bonuses; adaptation quality is measured separately (Section~\ref{sec:method_eval}).
    \item \textbf{Clipping to $[-1,1]$}: limits outlier steps that could destabilise value networks \cite{mnih_dqn_2015}.
    \item \textbf{Simulated correctness}: \texttt{last\_answer\_wrong} is drawn with probability $\max(0.2,\, 1-k)$, linking performance to knowledge without a full item bank.
\end{itemize}

\subsection{Synthetic Student Modeling}\label{sec:method_synthetic_student}

\paragraph{Why synthetic students?}
Training RL policies directly on minors or captive classroom populations raises ethical issues (consent, harm from poor policies, privacy). Real studies are also slow, expensive, and high-variance. Simulation is standard in adaptive learning comparisons when the goal is to compare \emph{algorithms} under controlled conditions \cite{azoulay_adaptive_2021,perez_emotions_2024,deshmukh_developing_2025}. This thesis uses simulation for safe offline training, not as a claim that the simulator equals human learning.

\paragraph{Population.}
\texttt{generate\_population} creates $10{,}000$ students with personality parameters:
\begin{itemize}
    \item $\gamma_s \sim \mathcal{U}(0.1, 1.0)$ --- learning rate multiplier;
    \item $\beta_s \sim \mathcal{U}(0.1, 1.0)$ --- sensitivity to hard tasks;
    \item $\lambda_s \sim \mathcal{U}(0.01, 0.3)$ --- forgetting rate;
    \item $\rho_s \sim \mathcal{U}(0.1, 1.0)$ --- patience (frustration recovery).
\end{itemize}
Types (\texttt{fast\_learner}, \texttt{slow\_learner}, \texttt{easily\_frustrated}, \texttt{patient}) are derived from thresholds on these parameters for analysis tables only.

\paragraph{Knowledge update (example).}
Each action maps to a base knowledge increment scaled by $\gamma_s$, minus optional decay when engagement is very low. For instance, \texttt{harder\_question} adds $0.07 \gamma_s$ before noise and clipping. This is a transparent rule set, not a fitted cognitive model.

\paragraph{Affect updates.}
Frustration decreases for supportive actions $\{$hint, scaffold, pacing, strategy, autonomy$\}$; increases more when harder questions are chosen under confused or frustrated emotions. Engagement rises for motivational, reflection, and autonomy actions. Confusion drops for hint, strategy, and explanation. Boredom rises when engagement is low. Each update adds $\mathcal{N}(0, 0.02^2)$ noise and clips to $[0,1]$.

\paragraph{Limitations of realism.}
The simulator does not model item content, prior knowledge domains, or social context. Emotional dynamics are Markovian on low-dimensional scalars. Parameters are uniform, not calibrated to DAiSEE or ASSISTments logs. Any policy improvement is \emph{internal validity} inside this simulator; external validity requires future human studies (Section~\ref{sec:method_rl_limitations}).

\subsection{PPO Algorithm}\label{sec:method_ppo}

\paragraph{RL foundations.}
The policy $\pi_\theta(a|\mathbf{o})$ parameterises action probabilities; the value function $V_\phi(\mathbf{o})$ estimates expected return. PPO is an actor--critic method that updates both while limiting policy change per minibatch \cite{schulman_ppo_2017,axak_adaptive_nodate,guzman_developing_2025}.

\paragraph{Why PPO?}
PPO was selected as the primary learner because it is stable on continuous and discrete control, widely used in SB3, supports vector observations without hand-crafted features, and works well with moderate sample budgets ($50$k steps). Compared to vanilla policy gradients, the clipped surrogate reduces destructive large updates. Compared to DQN (also implemented as baseline), PPO handles the full action distribution and integrates cleanly with action masking via \texttt{MaskablePPO}.

\paragraph{Clipped objective.}
Let $r_t(\theta) = \pi_\theta(a_t|\mathbf{o}_t) / \pi_{\theta_{\mathrm{old}}}(a_t|\mathbf{o}_t)$. PPO maximises
\begin{equation}
    L^{\mathrm{CLIP}}(\theta) = \mathbb{E}_t\left[
        \min\bigl(
            r_t(\theta) \hat{A}_t,\;
            \mathrm{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\,\hat{A}_t
        \bigr)
    \right],
    \label{eq:ppo_clip}
\end{equation}
where $\hat{A}_t$ is an advantage estimate and $\epsilon = 0.2$ is the clip range (\texttt{PPO\_CLIP\_RANGE}). Equation~\eqref{eq:ppo_clip} means that if the new policy becomes much more likely to take an action that already had positive advantage, the gradient is capped---preventing collapse after one lucky batch.

\paragraph{Exploration vs.\ exploitation.}
During training, stochastic sampling plus entropy bonus (\texttt{ent\_coef = 0.01}) encourages exploration among \emph{legal} actions. At evaluation, actions are chosen deterministically from the masked distribution.

\subsection{Training Procedure}\label{sec:method_rl_training}

Training is orchestrated by \texttt{main\_experiment.py}. For each algorithm in $\{$PPO, DQN, Bandit\_DQN$\}$ and each seed in a fixed list of ten seeds, the agent trains for \texttt{TOTAL\_TIMESTEPS = 50{,}000}, then saves weights under \texttt{RL\_Module/models/}. Rule-based and random agents skip training.

\paragraph{Procedure per seed.}
\begin{enumerate}
    \item \texttt{set\_all\_seeds(seed)} for Python, NumPy, and PyTorch.
    \item Build environment: PPO uses \texttt{ActionMasker} + \texttt{Monitor}; DQN uses \texttt{DQNSafeEnv} to resample illegal actions during training.
    \item \texttt{model.learn(total\_timesteps=50000)}.
    \item Save checkpoint to \texttt{models/\{Algorithm\}\_\{seed\}}.
\end{enumerate}

\paragraph{Episode batching.}
PPO collects rollouts of \texttt{n\_steps = 2048} before each update; multiple episodes may fit in one rollout. Episode boundaries are handled inside SB3 when \texttt{terminated} or \texttt{truncated} is true.

\subsection{Adaptive Tutoring Policy}\label{sec:method_policy}

After training, the PPO policy maps $\mathbf{o}_t$ and $\mathbf{m}_t$ to $a_t$. The policy is \emph{adaptive} because the same observation vector can yield different actions as knowledge and affect change; it is not a fixed script.

The rule-based baseline (\texttt{RuleBasedAgent}) implements a priority waterfall (persistent frustration $\rightarrow$ pacing; frustrated $\rightarrow$ pacing; low knowledge $\rightarrow$ scaffold; high confusion $\rightarrow$ explanation; etc.) and picks the first masked candidate. This represents a static expert heuristic rather than a learned value function.

The \texttt{BEST\_ACTION\_MAP} in \texttt{mdp\_definition.py} lists pedagogically appropriate actions per emotion for \textbf{evaluation only} (adaptation accuracy metric). It is never used in training or reward computation, avoiding circular evaluation.

\subsection{Emotion and Engagement Modeling}\label{sec:method_emotion_engagement}

\paragraph{Discrete emotion.}
\texttt{emotion\_id} $\in \{0,1,2,3\}$ corresponds to confused, bored, frustrated, engaged. In \textbf{synthetic mode} (default experiments), \texttt{FERAdapter} sets emotion from thresholds on $(f, c, b)$: e.g.\ $f>0.6 \Rightarrow$ frustrated. In \textbf{live mode} (\texttt{USE\_REAL\_FER=True}, future deployment), multilabel FER outputs are mapped to a single dominant label with confidence gating (\texttt{FER\_CONFIDENCE\_THRESHOLD = 0.5}).

\paragraph{Engagement and frustration in the loop.}
Engagement enters the observation and reward ($\Delta e$). Frustration drives masking, persistent flags, dropout, and reward penalties. Persistent frustration turns on after frustration exceeds $0.7$ for three consecutive steps and turns off when $f < 0.5$.

\paragraph{Relation to FER chapter.}
The FER module (Section~\ref{sec:method_architecture}) produces continuous scores for boredom, engagement, confusion, and frustration on DAiSEE. The RL module consumes a \emph{compatible} four-way discrete label at the interface. Closing the full webcam loop is implemented but not evaluated in the main thesis runs; results chapter should report simulator-based RL unless live FER experiments are explicitly added.

\subsection{Evaluation Methodology}\label{sec:method_eval}

\paragraph{Protocol.}
After training, each agent is evaluated for \texttt{EVAL\_EPISODES = 1000} episodes per seed with deterministic PPO predictions. Step-level and episode-level CSV logs are written to \texttt{RL\_Module/logs/}.

\paragraph{Metrics.}
\begin{itemize}
    \item \textbf{Mean episode reward}: average sum of $r_t$ per episode; primary RL performance indicator.
    \item \textbf{Learning gain}: mean normalized knowledge gain from episode start to end.
    \item \textbf{Success rate}: fraction of episodes with final $k>0.8$, $f<0.3$, $c<0.4$.
    \item \textbf{Dropout rate}: fraction ending in frustration dropout.
    \item \textbf{Adaptation accuracy}: fraction of steps where the action belongs to \texttt{BEST\_ACTION\_MAP} for current emotion (post-hoc pedagogical alignment, not used in training).
    \item \textbf{Convergence}: rolling standard deviation of episode rewards below $0.05$ over a window of $50$ episodes (exploratory diagnostic).
\end{itemize}

\paragraph{Statistical aggregation.}
Results are aggregated over ten seeds (\texttt{SEEDS = [42, 0, 1, \ldots, 314]}). For each metric, the mean and $95\%$ confidence interval are computed using the normal approximation: mean $\pm 1.96 \times \mathrm{SE}$.

\paragraph{Simulated evaluation limits.}
All metrics are simulator-internal. High reward does not automatically imply better human learning. External validity requires classroom or online user studies with the FER module enabled.

\subsection{Baselines and Comparisons}\label{sec:method_baselines}

Five agents are compared under the same environment and seeds:
\begin{enumerate}
    \item \textbf{PPO} (MaskablePPO) --- primary method;
    \item \textbf{DQN} --- value-based baseline with action resampling when masked;
    \item \textbf{Bandit\_DQN} --- LinUCB on emotion context when $|\Delta \iota| \geq 1$, else DQN;
    \item \textbf{Rule} --- hand-crafted priority rules;
    \item \textbf{Random} --- uniform over legal actions.
\end{enumerate}
This mirrors comparative adaptive learning studies that place RL, bandits, and rules on common ground \cite{azoulay_adaptive_2021}.

\subsection{Sensitivity Analysis}\label{sec:method_sensitivity}

\texttt{sensitivity\_analysis.py} runs a $3 \times 3$ factorial design: three reward weight presets (\texttt{equal}, \texttt{knowledge\_priority}, \texttt{affective\_priority}) $\times$ three action-masking threshold presets (\texttt{default}, \texttt{stricter}, \texttt{looser}). Each cell trains all five algorithms for \texttt{5{,}000} timesteps on seed $42$ and evaluates $50$ episodes.

Spearman rank correlation compares algorithm rankings between cells. High $\rho$ ($\geq 0.9$) suggests conclusions are robust to reasonable hyperparameter changes; low $\rho$ flags sensitivity. Short timesteps are a deliberate cost-saving choice for sensitivity only; main experiments use $50{,}000$ steps.

\subsection{Ablation Study}\label{sec:method_ablation}

Two ablation layers are implemented.

\paragraph{Emotion-aware vs.\ emotion-free PPO.}
\texttt{ablation\_study.py} trains and compares PPO with full emotion in $\mathbf{o}_t$ versus PPO with \texttt{ablation\_no\_emotion=True} (dimension $5$ zeroed). Metrics: mean episode reward, learning gain, adaptation accuracy (success rate excluded by design in the ablation script).

\paragraph{Full RL ablation (\texttt{run\_ablation}).}
\texttt{metrics.run\_ablation} trains PPO, DQN, and Bandit\_DQN with and without emotion for all three RL algorithms on a single seed---useful for quick checks; publication figures use the dedicated ablation study script.

The hypothesis tested is that emotion information improves pedagogical alignment and reward, not that emotion is the only useful signal (knowledge and affect scalars remain in both variants).

\subsection{Implementation Details}\label{sec:method_rl_implementation}

\paragraph{Software stack.}
Python 3; \texttt{gymnasium} $\geq 0.29$; \texttt{stable-baselines3} $\geq 2.2$; \texttt{sb3-contrib} (MaskablePPO); \texttt{torch} $\geq 2.0$; \texttt{numpy}, \texttt{pandas}, \texttt{matplotlib}, \texttt{scipy}, \texttt{pytest}.

\paragraph{Reproducibility.}
\texttt{set\_all\_seeds} fixes Python, NumPy, and PyTorch RNGs. Population generation is seeded per run. Evaluation uses \texttt{reset(seed=seed + episode\_id)} for episode diversity while keeping training reproducible.

\paragraph{Hardware.}
Experiments are designed to run on a single CPU or GPU machine; no distributed training is required. Exact hardware can vary; training $50$k steps per seed is feasible on a laptop-grade GPU or CPU within reasonable time (order of minutes per seed for PPO on this small MLP).

\subsection{Ethical Considerations}\label{sec:method_rl_ethics}

Offline simulation avoids exposing learners to untested policies. If the system is deployed with live FER, informed consent, transparent use of webcam data, and the right to opt out are required \cite{fernandez-herrero_evaluating_2024,vistorte_integrating_2024,florestiyanto_emotion_2024}. Action masking and frustration dropout encode a minimal ``do no harm'' bias, but they do not replace ethical review for human trials.

Policies trained on synthetic students may still reflect biases in hand-written transition rules (for example, uniform personality sampling). Fairness across demographic groups is not addressed in the simulator and remains future work.

\subsection{Limitations}\label{sec:method_rl_limitations}

\begin{itemize}
    \item \textbf{Simulator fidelity}: transitions are rule-based, not data-driven.
    \item \textbf{FER loop}: main experiments use synthetic emotion; live FER integration is unvalidated in reported runs.
    \item \textbf{No real items}: answers are probabilistic functions of $k$, not an item bank.
    \item \textbf{Single task domain}: no multi-subject curriculum.
    \item \textbf{Adaptation accuracy map}: expert table for evaluation only; labels are design choices, not ground truth from teachers.
    \item \textbf{Sample budget}: $50$k steps may under-train relative to large industrial RL setups; sensitivity uses even fewer steps.
\end{itemize}

\subsection{Chapter Summary}\label{sec:method_rl_summary}

This section specified an adaptive tutoring system as a Gymnasium MDP with a six-dimensional state, ten pedagogical actions, action masking for safety, a multi-term clipped reward with normalized knowledge gain, and a synthetic student population of $10{,}000$ profiles. PPO with masking is the primary learner; DQN, LinUCB+DQN, rule-based, and random agents provide baselines. Training is offline and reproducible; evaluation reports reward, learning gain, success, dropout, and adaptation accuracy across ten seeds, with ablation and sensitivity tools to test the role of emotion and hyperparameters. The FER module supplies the deployment path for real affective input; the quantitative results of the adaptation module are reported in Chapter~\ref{chap:results}, together with the limitations above kept in mind when interpreting simulator gains.
